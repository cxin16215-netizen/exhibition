立项阶段栖金历史版本

从优惠计算题出发

建立多平台优惠结算，发现全局最低价评级的覆盖问题。

展开过程 +收起 −
发现的问题
折扣层层叠加，很难分清平台声称的优惠与真正的现金支出。最初希望把识破规则、反过来利用规则做成游戏。
设计决策
把商品、店铺、平台优惠按顺序结算，采用数据配置；曾考虑用求解器找最低价，再给玩家评级。
工作流程
先定义优惠结算顺序 → 用数据配置商品、店铺和平台 → 尝试求解与评级 → 记录拆单和平台规则的覆盖缺口。
结果与证据
形成了订单与多平台比较的系统基础，也暴露出一个问题：计算上的最优，未必等于玩家想过的生活。
依据

《立项文档》《技术债_求解器与评级》；早期购物设计讨论

10.04—10.05栖金已实现

把省下的钱接回生活

从优惠计算扩展到采购、收货、摆放与生活需求。

展开过程 +收起 −
发现的问题
只让玩家追最低价，会让家具、屋子和角色成为结算表的装饰。
设计决策
引入小窝、生活需求与月度节奏。必需采购提供清晰目标；心愿与更舒适的替代品保留自愿选择，不把多花钱一律判错。
工作流程
复核单纯最低价目标 → 写生活需求与月度方案 → 接入小窝采购、收货、摆放和角色反馈。
结果与证据
一月搬进毛坯小窝，采购、收货、摆放和角色反应开始连成体验。故事中的主角是龙娘本人。

10.05 起栖金已实现

先让“省了多少”可信

区分购物内容变化、现金支出和其他权益，避免虚报省钱。

展开过程 +收起 −
发现的问题
不同商品组合的两个购物车，不能直接相减就称为省钱；本金、奖励、借贷也不应混成同一项收益。
设计决策
比较当前与上一份非空草稿时提示内容是否变化；结账反馈对照玩家自己的方案，区分现金和其他权益。前三旬给出采购与回家引导。
工作流程
对照草稿与订单口径 → 区分内容变化和现金权益 → 接入反馈与前三旬引导 → 保留逻辑检查和未试玩边界。
结果与证据
省钱反馈从抽象评分转为能解释的订单变化；首月月初发生活费，中下旬不反复补钱，月末停下来回看。
依据

系统贯穿栖金已实现

让订单真正成为家里的东西

让付款、送达、消耗和退款共同决定任务状态。

展开过程 +收起 −
发现的问题
如果付款、送达、收好、消耗和退款互不相认，叙事就会出现尚未收到却能使用的物品。
设计决策
按真实订单与包裹状态判任务；允许已有同类物品满足需求；材料实际领取后才能消耗，退款后重新检查对应条件。
工作流程
逐条核对任务所需物品状态 → 串联订单、包裹、库存与消耗 → 为替代物与退款重检保留规则。
结果与证据
采购不再只是点完对话。订单、收纳和故事任务共用物品状态，跨旬送达也成为节奏的一部分。
依据

《包裹送达与整理》《格子储物与交互UI》及二至六月实现说明

10.06栖金已实现

二月：整理，而非再买一个收纳盒

已有杯子与宝箱也能完成热饮整理，收纳盒保持可选。

展开过程 +收起 −
发现的问题
热饮需求很容易被扩成一串强制购物任务，珍惜包装的角色习惯也容易只停在台词里。
设计决策
水壶与已有可用杯子组成真实采购需求；宝箱也能完成摆放。通过留下说明书、舍不得扔空白卡片的小动作表现人物。包装纸只作剧情道具，不另加垃圾库存、清洁惩罚或物理清理系统。
工作流程
确认热饮与收藏习惯 → 接入采购替代和真实摆放 → 制作包装整理小剧场 → 检查提前退出与重复完成。
结果与证据
包装整理是可重入的小剧场，提前退出不算完成；收纳盒是可选物，不成为剧情门票。

前三月迭代栖金已实现

三月：给“不下单”留一个结局

减少强制采购，允许下旬零订单完成主线。

展开过程 +收起 −
发现的问题
每旬都要求新消费，会让“留着最好的那一口”再次变成购买清单。
设计决策
主线只需要即食牛肉与配菜，下旬允许零订单；通过先藏起最好的一份、后来决定今天吃掉，完成生活里的小转变。
工作流程
收缩必买清单 → 设计藏起与吃掉最好一份的动作 → 接入收货、摆放、对白和零订单结算。
结果与证据
已经买过的不必重买，不加饥饿、烹饪设备等额外门槛。促销“最后机会”反复出现，作为世界的幽默而非强制操作。
依据

10.08 起栖金已实现

四月：同一目标，多条采购路线

同一修箱目标支持替代材料、跨平台采购与可撤回行李草案。

展开过程 +收起 −
发现的问题
修旧箱如果只能点一个指定商品，就无法发挥跨平台比较与库存的系统价值。
设计决策
提供整套工具或护角加底板两条修复方案，处理满减、运费、合作价与真实材料消耗。行李草案复用已有物品，允许撤回。
工作流程
比较修箱路线 → 接入采购配表与材料消耗 → 复用任务纸及手机入口 → 扩充支线、演出和试玩路径；旧稿由总案更新。
结果与证据
采购入口回到既有任务纸和手机；修箱增加回程容量，不虚增房间容量。咨询、鉴宝与可选装饰为支线。
待验证
整段画面试玩尚未完成。

五月内容迭代栖金已实现

五月：购买后的制作与分享

把实际材料消耗、制作和聚会接成三旬流程。

展开过程 +收起 −
发现的问题
如果采购后只剩一句完成提示，物品与生活之间的联系仍然很薄。
设计决策
把材料、制作和聚会串联；制作消耗实际领取的材料，作品选择保留不同趣味，不按花钱多少排好坏。
工作流程
确定制作与聚会目标 → 配置三旬任务 → 串联送达、材料消耗与选择反馈 → 留下实现及试玩说明。
结果与证据
六项任务衔接三旬流程；跨旬包裹、已有杯子和其他旧物继续参与，不需要为每一幕再买一套。
待验证
画面与交互仍需沿试玩路径复核。

六月内容迭代栖金已实现

六月：让比较方案经过真实结账

把套装、拆单、等待和运费比较接入实际结账。

展开过程 +收起 −
发现的问题
购物方案不能只比较标价，还涉及原有数量、套装、库存、拆单、等待和运费。
设计决策
让这些路线经过实际结算与收货；退款使相关确认失效。允许不购买而欣赏、整理已有物品。
工作流程
列出数量、套装、库存和等待方案 → 走真实结账与收货 → 检查退款失效和实际消耗 → 记录核心、资源检查及未完成的UI验证。
结果与证据
文档记录了221项核心检查与26项原生资源检查通过，覆盖状态与资源接入。
待验证
完整界面的自动流程尚未跑通，需要整段试玩确认。

10.12栖金已实现

七月：用轻量交互承接夏天

接入便当、饮品与谜题，不用高分强迫购物。

展开过程 +收起 −
发现的问题
七月需要生活变化，但不希望用小游戏高分再次强迫玩家消费。
设计决策
加入6×5便当摆放、旋转与食物邻接约束；饮品按容量与配方快照结算；饼干谜题可提示、可揭晓。
工作流程
确定夏日交互约束 → 接入便当、饮品快照与可提示谜题 → 核对场景物品和真实库存 → 记录核心与原生检查结果。
结果与证据
三旬内容接入。场景供应品明确区别于玩家库存，剧情选择不因小游戏被跳过；文档记录463项核心、33项原生检查。
待验证
完整界面自动化尚未完成；八月以后的内容仍在规划。
依据

10.15—10.22栖金已实现

把可复用功能拆成独立验证模块

独立验证17个功能模块，再与主流程集成状态分开记录。

展开过程 +收起 −
发现的问题
主流程越来越大，存档、售后、限时活动等功能如果一起改，很难单独验证。
设计决策
用独立演示模块承载标题、存档、包裹、客服、秒杀和其他系统，先跑通各自的状态与界面。
工作流程
按功能拆分独立演示 → 分别实现与验证 → 汇总交付结果 → 明确哪些尚不能视作主流程集成。
结果与证据
两份交付汇总记录了17个独立模块，为后续接入提供材料。

独立模块尚未全部接入主流程；10月22日汇总检查 242 项，241 项通过，1 项为既有失败。

10.26 讨论栖金方案

重新确认：节省与心愿都应得到回应

确认节省与心愿分别得到反馈，后续内容仍属设计方向。

展开过程 +收起 −
发现的问题
只奖励最省的一条路线，会削弱角色关系、温暖生活与自主选择。
设计决策
省钱路线给准确的余额与事实反馈；愿意为小心愿多花一点，也获得具体生活事件。错误不设计成不可逆的生活惩罚。
工作流程
复核购物体验目标 → 讨论节省、心愿与长期目标 → 确认反馈方向，暂不把讨论结果列为实现。
结果与证据
确认后续修改的判断标准：多平台仍有策略，角色和房间也要回应玩家的选择。长期攒钱与即时心愿可以形成张力。
待验证
长期目标、结局回响与时间线调整仍是设计方向，尚未落地。
依据

10月26日项目设计复核；《全年回家主线与魔法金币》《房间阶段变化设计》为相关方案
